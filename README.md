# Перший прототип: Uno R3 + датчик + фоторезистор

## Якщо використовуєш HC-SR501 PIR

Відкрий **`greentech_pir/greentech_pir.ino`**. Файл `greentech_hcsr04.ino` призначений лише для ультразвукового HC-SR04: не підключай OUT датчика PIR до D2, поки на Uno працює той скетч.

1. Від'єднай USB. Зніми HC-SR04 разом із його чотирма дротами: VCC, GND, Trig до D2, Echo до D7. Сам датчик збережи.
2. Залиш фоторезистор, резистор 10 кОм і три дроти Uno до макетної плати як є.
3. Поки PIR ще не підключений, підключи USB й завантаж `greentech_pir.ino`, вибравши Arduino Uno та відповідний порт. Додаткові бібліотеки не потрібні.
4. Знову від'єднай USB. Підключи три контакти HC-SR501 за їхніми написами, не за положенням на фото:

| Контакт HC-SR501 | Підключення |
|---|---|
| VCC / + | b1 макетної плати, з'єднаний із Uno 5V через a1 |
| GND / − | b10 макетної плати, з'єднаний із Uno GND через a10 |
| OUT | Uno D2 |

5. D7 тепер вільний. D3 залиш відкритим; додаткова перемичка D3–GND примусово вмикає LED. Окремий LED не потрібен: використовується вбудований «L».
6. Підключи USB. Відкрий Serial Monitor на **9600 бод**. Зачекай **60 секунд**; під час прогріву LED ON.
7. Якщо на PIR є перемичка H/L, вибери H. Зменш апаратну затримку TIME за інструкцією модуля. Програмні 10 секунд починаються після останнього HIGH із PIR, тому апаратна затримка додається до них.

```text
Motion: YES | Light (raw): 512 | LED: ON
```

PIR показує рух, а не відстань. `Motion: NO` не доводить, що людей немає: нерухома людина може не викликати сигнал. Від'єднання або несправність із постійним LOW цей модуль не може самостійно повідомити. Освітленість поки лише записується у вивід. Програма `record_csv.py` нижче призначена для CSV-режиму HC-SR04, а цей мінімальний PIR-скетч має лише читабельний вивід.

Перевірка PIR-коду:

```sh
arduino-cli compile --fqbn arduino:avr:uno greentech_pir
clang++ -std=c++11 -Wall -Wextra -Werror -I test-support check_pir.cpp -o /tmp/greentech-pir-check
/tmp/greentech-pir-check
```

## Якщо використовуєш HC-SR04

Це настільна перевірка відстані, освітленості й вбудованого світлодіода Uno. Окремий LED та резистор для нього не потрібні. HC-SR04 не визначає кількість людей або зайнятість класу. Живлення — лише USB; LED-стрічку й 230 В не підключаємо.

## 1. Підключення

Від'єднай USB перед підключенням дротів. Усі GND мають бути з'єднані. Орієнтуйся на написи біля контактів, а не на їхнє розташування на чужій фотографії.

| Деталь | Контакт | Куди підключити на Uno R3 |
|---|---|---|
| HC-SR04 | VCC | 5V |
| HC-SR04 | GND | GND |
| HC-SR04 | Trig | D2 |
| HC-SR04 | Echo | D7 |
| Фоторезистор | Перша ніжка | 5V |
| Фоторезистор | Друга ніжка | A0; до цієї ж точки — один кінець резистора 10 кОм |
| Резистор 10 кОм | Інший кінець | GND |
| Вбудований LED «L» | LED_BUILTIN / D13 | Уже підключений на Uno; дроти не потрібні |
| Ручне ввімкнення | Перемичка | Між D3 і GND; спочатку не встановлюй |

```text
5V ── фоторезистор ──┬── A0
                    └── 10 кОм ── GND
```

Фоторезистор не має полярності. Якщо рейки живлення макетної плати розділені посередині, використовуй одну суцільну ділянку або з'єднай відповідні ділянки перемичками.

### Точні отвори на стандартній макетній платі

Використовуй лише половину з літерами **a–e**. П'ять отворів одного номера на цій половині з'єднані між собою. Бічні рейки живлення тут не потрібні.

| Звідки | Куди |
|---|---|
| Uno 5V | a1 |
| Uno GND | a10 |
| Uno A0 | a5 |
| Фоторезистор, дві ніжки | e1 та e5 |
| Резистор 10 кОм, два кінці | c5 та c10 |
| HC-SR04 VCC | b1 |
| HC-SR04 GND | b10 |
| HC-SR04 Trig | Uno D2 |
| HC-SR04 Echo | Uno D7 |

Потрібні 3 дроти «тато–тато» між Uno та макетною платою і 4 дроти «тато–мама» для HC-SR04. Контакт D3 залиш відкритим. Для примусового ввімкнення LED його можна з'єднати додатковою перемичкою з вільним GND Uno.

**Echo HC-SR04 сумісний із 5-вольтовим Uno R3. Ця схема не призначена для прямого перенесення на 3,3-вольтові плати.** Не плутай контакт живлення 5V із цифровим D5.

## 2. Завантаження коду

1. Відкрий `greentech_hcsr04/greentech_hcsr04.ino` в Arduino IDE.
2. Підключи Uno через USB-кабель із передаванням даних.
3. Вибери плату **Arduino Uno** з пакета **Arduino AVR Boards**, а також фактичний USB-порт плати.
4. Натисни Verify, потім Upload. Додаткові бібліотеки не потрібні.
5. Відкрий Serial Monitor на **9600 бод**.

Типовий рядок тепер зрозумілий без розшифрування CSV:

```text
Distance: 32.4 cm | Light (raw): 512 | LED: ON
```

`Distance` — виміряна відстань у сантиметрах із одним знаком після крапки. `Light (raw)` — показник фоторезистора 0–1023, не люкси. `LED` — стан вбудованого світлодіода. За відсутності коректного відлуння замість відстані з'являється `NO VALID ECHO`; старе значення не показується як нове.

Натисни Code → Download ZIP на GitHub, розпакуй архів і відкрий скетч із папки `greentech_hcsr04`. Для першого тесту достатньо Arduino IDE; Python потрібен лише для автоматичного CSV.

## 3. Перевірка на столі

1. Направ датчик на тверду пласку поверхню приблизно за 1 м. Очікуй `Distance: 100.0 cm` або близький показник та `LED: OFF` після початкового вимірювання.
2. Постав перед ним книжку або картон на 30–40 см. LED має ввімкнутися.
3. Перемісти предмет на 55 см: LED залишається ввімкненим. Після виявлення ближче 50 см сигнал підтримується до 60 см включно.
4. Поверни предмет далі 60 см: через 10 секунд після останнього близького показника LED вимкнеться. Предмет на 55 см після вимкнення не вмикає LED заново; для ввімкнення потрібна відстань менше 50 см.
5. Закрий фоторезистор рукою, потім освіти його: `Light (raw)` має змінюватися. У цьому режимі освітленість не керує LED.
6. З'єднай D3 із GND: LED ON незалежно від відстані. Прибери перемичку — повернення до автоматики. Це проста перемичка без програмного усунення брязкоту контактів.
7. Якщо датчик не отримує коректного відлуння три вимірювання поспіль, з'являється `Sensor fault: LED forced ON`, LED ON. Одне коректне вимірювання скидає цю помилку. Повторні помилки можуть знову її активувати.

Неотримане відлуння — не доказ порожньої кімнати: поверхня може бути під кутом, поглинати звук або бути поза діапазоном. Для першого тесту книжка чи картон надійніші за одяг або вузький предмет. Для перевірки помилки можна спрямувати датчик у напрямку без відповідної поверхні в межах діапазону; не висмикуй живлення модуля під час роботи.

Робочий номінальний діапазон HC-SR04 — 2–400 см. Вимірювання виконуються раз на 100 мс; очікування відлуння обмежене 25 мс. Ручна команда обробляється в циклі; очікування датчика може затримати її до приблизно 25 мс. Початковий LED ON триває до першої спроби вимірювання; окремого 60-секундного прогріву PIR тут немає.

## 4. Автоматичний CSV на Mac

Для запису CSV зміни на початку скетчу `CSV_OUTPUT = false` на `CSV_OUTPUT = true` і повторно завантаж код. За замовчуванням працює читабельний вивід для Serial Monitor; програма `record_csv.py` читає лише режим CSV.

Спочатку переконайся через Serial Monitor, що показники правильні. Потім **закрий Serial Monitor і Serial Plotter**: одночасний доступ заважає запису. Під час повторного завантаження скетчу спочатку зупиняй програму запису.

Відкрий Terminal у папці репозиторію, де лежить `record_csv.py`, і знайди порт:

```sh
ls /dev/cu.usb*
```

Підстав фактичний порт із виводу; назва нижче — приклад:

```sh
python3 record_csv.py /dev/cu.usbmodem1101
```

Потрібен Python 3; сторонні Python-пакети не потрібні. Якщо `python3` відсутній, поки використовуй Serial Monitor.

Коли з'явиться `Recording ...`, натисни RESET на Uno один раз. Записуються лише нові отримані дані; історія з Arduino не завантажується. **Ctrl+C** зупиняє запис. CSV з назвою на кшталт `greentech-20261019-120000.csv` створюється в поточній папці. Наявний файл не перезаписується.

Можна задати назву:

```sh
python3 record_csv.py /dev/cu.usbmodem1101 --output classroom-test-01.csv
```

Стовпці:

```csv
received_utc,session,uptime_ms,distance_cm,echo_ok,ldr_raw,near,fault,override,lamp
```

- `received_utc`: час отримання на Mac у UTC, залежить від правильності його годинника; це не час RTC на Arduino.
- `session`: новий сеанс після виявленого перезапуску або переповнення лічильника часу.
- `uptime_ms`: мілісекунди від запуску Arduino.
- `distance_cm`: відстань; порожнє поле означає недійсне вимірювання, не 0 см.
- `echo_ok`: коректне відлуння в номінальному діапазоні.
- `ldr_raw`: сирий показник 0–1023, не люкси.
- `near`: поточний коректний сигнал близького предмета з урахуванням порогів 50/60 см.
- `fault`: три послідовні невдалі вимірювання.
- `override`: перемичка D3–GND встановлена.
- `lamp`: команда світлодіоду; може залишатися 1 після `near=0` через затримку або захисний режим.

Рядок надсилається щосекунди, а також при зміні команди LED або стану помилки. CSV містить знімки останнього вимірювання, а не всі десять вимірювань за секунду. Після кожного рядка Python скидає власний файловий буфер, але це не гарантує збереження останніх рядків у разі раптового вимкнення Mac. Для збереження даних ноутбук має працювати, не спати й залишатися підключеним. Без живлення нові вимірювання не записуються.

## 5. Параметри наступного тесту

На початку скетчу можна змінювати `ENTER_MM`, `EXIT_MM`, `HOLD_MS`. Наприклад, для затримки 10 хвилин: `HOLD_MS = 600000UL`. Потім знову завантаж код. Наразі немає команд керування з Mac, RTC, SD, реального розкладу, керування за освітленістю або датчика PIR — це наступні узгоджені кроки.

## Перевірка коду

Скетч у читабельному режимі компілюється для `arduino:avr:uno`, ядро AVR 1.8.8: **3556 байтів flash, 210 байтів глобальної SRAM**. Програмні перевірки охоплюють пороги, гістерезис, затримку, помилки, відновлення, ручне ввімкнення, межі діапазону, переповнення `millis()` та текст відстані й помилок.

Фізична схема ще не перевірена. Джерело параметрів HC-SR04: [документація ElecFreaks, розміщена SparkFun](https://cdn.sparkfun.com/datasheets/Sensors/Proximity/HCSR04.pdf).

Щоб повторити програмні перевірки з кореня репозиторію:

```sh
arduino-cli compile --fqbn arduino:avr:uno greentech_hcsr04
clang++ -std=c++11 -Wall -Wextra -Werror -I test-support check_prototype.cpp -o /tmp/greentech-check
/tmp/greentech-check
python3 check_recorder.py
```
